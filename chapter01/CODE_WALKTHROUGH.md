# 第 1 章参考代码导读

参考文件：`D:\Code\hello-agents\code\chapter1\FirstAgentTest.py`

先不要从第一行死磕到最后一行。可以把整份代码看成 6 个零件。

## 1. 系统提示词：给模型一份工作说明

`AGENT_SYSTEM_PROMPT` 告诉模型：

- 你扮演旅行助手；
- 你能使用哪些工具；
- 每次应该输出 `Thought` 和 `Action`；
- 信息足够时用 `Finish[...]` 结束。

提示词只是发给模型的文字，不是 Python 的强制规则。模型仍有可能不按格式回答，所以后面的程序必须检查和处理异常输出。

## 2. 工具函数：程序真正能执行的能力

示例有两个普通 Python 函数：

- `get_weather(city)`：向天气网站发送 HTTP 请求；
- `get_attraction(city, weather)`：调用 Tavily 搜索。

模型自己不能直接执行这两个函数。模型只会生成类似下面的文字：

```text
Action: get_weather(city="北京")
```

真正执行函数的是我们编写的 Python 控制程序。

## 3. 工具注册表：工具名称与函数的电话簿

```python
available_tools = {
    "get_weather": get_weather,
    "get_attraction": get_attraction,
}
```

左边的字符串是模型需要说出的工具名称，右边是 Python 函数本身。程序查到名称后，才能找到并调用对应函数。

这正是 `warmup.py` 要先练习字典和函数的原因。

## 4. LLM 客户端：把消息发给模型服务

`OpenAICompatibleClient` 做了三件事：

1. 保存模型名称、API 密钥和服务地址；
2. 把 system/user 消息发送给兼容 OpenAI 格式的 API；
3. 从响应对象中取出模型回答。

这里的“客户端”可以理解为一个快递员：它负责把请求送到模型服务器，再把回复取回来。模型通常运行在远程服务器上，而不是这台电脑里。

## 5. 历史记录：让下一轮知道前面发生了什么

`prompt_history` 是一个列表。程序依次向其中添加：

```text
用户请求
模型的 Thought/Action
工具返回的 Observation
模型的下一次 Thought/Action
...
```

每轮调用模型前，程序用 `"\n".join(prompt_history)` 把这些记录重新拼成一段文字。没有这一步，模型下一轮就不知道工具刚才返回了什么。

## 6. 行动循环：Agent 最核心的部分

教程最多循环 5 次，每轮执行：

1. 组合历史记录；
2. 调用模型；
3. 从模型回答中寻找 `Action`；
4. 如果是 `Finish`，结束任务；
5. 否则找到并执行工具；
6. 把工具结果记为 `Observation`；
7. 回到下一轮。

因此，这一章的最小 Agent 可以写成：

```text
while 任务没有结束:
    模型输出下一步行动
    程序执行行动
    程序把结果交给模型
```

## 教材代码中需要提前知道的简化点

这些不是要求你现在修复，而是避免把教学示例误认为生产代码。

### 密钥被写在代码位置

示例用 `YOUR_API_KEY` 作占位。真实密钥不应直接写进 `.py` 文件。我们的练习会从 `.env` 加载，并用 `.gitignore` 排除它。

### HTTP 请求没有超时

`requests.get(url)` 如果远端一直不响应，程序可能等很久。实际项目通常写成 `requests.get(url, timeout=10)`。

### 正则解析比较脆弱

代码多次直接对正则结果调用 `.group()`。如果模型返回格式不符合预期，匹配结果可能是 `None`，随后引发错误。我们会先检查匹配是否成功。

### 工具参数完全来自模型

模型可能给错工具名、漏掉参数或传入错误类型。实际 Agent 需要参数验证，不能直接相信模型输出。

### `Thought` 不等于真正可靠的推理

它只是模型生成的一段文字。判断 Agent 是否有效，要看行动是否正确、工具结果是否被正确使用，以及最终答案是否可验证。

## 本章动手路线

1. 完成 `warmup.py`，弄懂函数、字典和动态调用。
2. 不接 LLM，手工给出工具名和参数，跑通一次工具调用。
3. 接入 LLM，只让它返回行动，不执行工具。
4. 加入工具执行和历史记录，形成完整循环。
5. 新增一个自己的工具，并故意制造一次错误来练习调试。
