# 第 8 章：记忆与检索

教程：[第八章 记忆与检索](https://hello-agents.datawhale.cc/#/./chapter8/%E7%AC%AC%E5%85%AB%E7%AB%A0%20%E8%AE%B0%E5%BF%86%E4%B8%8E%E6%A3%80%E7%B4%A2)

## 本章目标

在第七章的 `Message`、`Agent` 和工具注册表基础上，区分三种容易混淆的东西：当前会话的临时消息历史、跨会话保存并能检索的记忆、从外部文档取证的 RAG。先用离线小练习理解存储、检索、来源标注和生命周期，再按实际需要考虑在线模型与数据库。

## 穿插安排

1. **8.1 概念与架构：**先读 8.1.1～8.1.3，到 8.1.4 前暂停。能说明第七章 `_history` 与长期记忆的区别，以及 `memory_tool` 和 `rag_tool` 各管理什么。8.1.4 的快速体验先只看总体流程，不申请 Qdrant、Neo4j 或嵌入服务账号。
2. **8.2 记忆系统：**读 8.2.1 的编码、存储、检索、整合、遗忘流程后，穿插一个本地记忆练习；优先用 Python 内存或本地文件理解生命周期与跨会话恢复，再读 8.2.3～8.2.5 中有关分类、检索和遗忘的关键设计。大型云数据库配置与四套完整实现暂不照抄。
3. **8.3 RAG：**先分清“文档准备”和“查询问答”两条流程，再做一个无需向量数据库和模型调用的最小检索练习：将短文档分块、按问题检索，并保留来源标识。之后再比较关键词、向量和高级检索方法，决定是否值得增加依赖。
4. **8.4 案例整合：**围绕“用户历史用记忆查、教材或资料用 RAG 查”理解路由与引用；只实现能证明数据流的小型离线案例，不复制整套智能助手或运行付费服务。
5. **8.5 收尾：**复跑已做练习，记录保留与跳过的理由，复盘“正确检索”与“有来源的回答”的区别，然后学习本章 Git 暂存、提交与推送。

## 本章验收与取舍

- 离线检查：`check_memory.py` 5/5、`check_rag.py` 4/4、`check_integrated.py` 4/4。
- 保留并亲手实现：
  - 记忆系统：工作记忆、重要性筛选转入长期记忆、会话结束清空工作记忆、JSON 本地持久化与恢复。
  - RAG 检索：按固定长度文本切分、携带来源信息（`source`、`chunk_id`）建立索引、关键词检索、规范化拼装带来源的上下文。
  - 案例整合：将记忆与 RAG 封装为工具接口、基于意图关键词的双向路由与保底策略、分段组装交付模型的 Prompt。
- 跳过：
  - Qdrant 向量数据库部署、Neo4j 知识图谱以及云端 Embedding API 申请，理由是本阶段核心在于搞懂数据流转机制与生命周期，离线原生 Python 方案无外部依赖、易验证、零成本。
  - Gradio Web 前端界面，理由是优先聚焦智能体核心后端与知识整合逻辑。

## 成本与环境约定

- 先做离线、可验证的最小版本；不因教程示例而自动安装 Qdrant、Neo4j、Docker 或下载本地嵌入模型。
- 若后面确实需要在线模型或数据库，先说明能多学到什么、所需配置和可能费用，再决定是否操作。
- 检索结果保留来源，避免把“模型生成的回答”误当成已核实的资料。
