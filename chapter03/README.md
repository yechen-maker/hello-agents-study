# 第 3 章：大语言模型基础

教程：[第三章 大语言模型基础](https://hello-agents.datawhale.cc/#/./chapter3/%E7%AC%AC%E4%B8%89%E7%AB%A0%20%E5%A4%A7%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B%E5%9F%BA%E7%A1%80)

## 本章目标

本章代码和数学内容较多，不一路读到底。每到一个暂停点，先用小实验把概念变成可观察的结果，再继续阅读。

学完后应当能够：

- 用通俗语言解释语言模型为什么是在“预测下一个 Token”。
- 说明 N-gram、RNN/LSTM 和 Transformer 分别解决了什么问题。
- 理解注意力、位置编码、因果掩码和 Decoder-Only 的作用。
- 实际比较不同提示方法和采样参数的输出。
- 观察一次简单的 BPE 合并过程。
- 理解模型选型、Token 成本和幻觉对 Agent 的影响。

## 穿插安排

### 阶段 1：N-gram——先把“语言概率”算出来

阅读 `3.1.1` 中 N-gram 部分及教程的第一个 Python 示例，然后暂停。

- [ ] 手算官方习题中的 `agent works` Bigram 概率。
- [ ] 创建 `ngram_demo.py`，亲手实现计数和概率连乘。
- [ ] 把语料中不存在的词放进句子，观察概率为什么变成 0。
- [ ] 用自己的话解释马尔可夫假设和数据稀疏问题。

这个实验只使用 Python 标准库，不需要安装新依赖。

### 阶段 2：词向量、RNN 与 LSTM

继续读完 `3.1.1`，然后暂停。

- [ ] 用二维坐标画出或打印几个简化词向量。
- [ ] 观察语义相近的向量为什么方向更接近。
- [ ] 用一句话解释 RNN 的隐藏状态相当于什么。
- [ ] 解释 LSTM 的遗忘门、输入门、输出门分别控制什么。

如果运行教程的 NumPy 示例，使用 `uv add numpy`，不使用 `pip install`。

### 阶段 3：Transformer 与注意力

阅读 `3.1.2` 时分块进行，不要求第一次就背公式或完整抄写整个 Transformer。

暂停点：

- [ ] 读完 Encoder-Decoder：画出输入从编码器到解码器的方向。
- [ ] 读完多头注意力：解释 Q、K、V 分别在做什么。
- [ ] 读完前馈网络：追踪一次张量维度的变化。
- [ ] 读完位置编码：解释为什么仅有注意力看不出词序。

随后创建 `attention_demo.py`，用一个极小输入观察注意力权重和张量形状。PyTorch 依赖到这个暂停点再按本机环境安装，不提前安装整套库。

### 阶段 4：Decoder-Only 与自回归生成

读完 `3.1.3` 后暂停。

- [ ] 手工模拟三步“预测下一个 Token → 拼回输入”的过程。
- [ ] 画一个 4×4 因果掩码，标出每个位置能看见哪些 Token。
- [ ] 解释为什么训练可以并行，而实际生成仍需逐 Token 进行。
- [ ] 对比 Encoder-Decoder 与 Decoder-Only。

### 阶段 5：提示工程——必须动手对比

阅读 `3.2.1` 时创建 `prompt_experiment.py`，复用第一章的大模型调用方式。

- [ ] 对同一分类任务比较 Zero-shot、One-shot、Few-shot。
- [ ] 对同一问题比较不同 Temperature 的多次输出。
- [ ] 要求模型输出固定 JSON，观察它是否始终遵守格式。
- [ ] 保存输入和输出，写下哪种提示更稳定以及原因。

这是本章对 Agent 开发最重要的实践之一。

### 阶段 6：Token 与 BPE

阅读 `3.2.2` 后暂停。

- [ ] 手工完成两轮最高频相邻字符对合并。
- [ ] 创建 `bpe_demo.py`，运行教程中的简化 BPE。
- [ ] 修改语料，预测下一次会合并哪一对，再运行验证。
- [ ] 说明 Token 数量为什么影响上下文长度、速度和费用。

### 阶段 7：本地开源模型

阅读 `3.2.3`，但不要立即照抄 `pip install transformers torch`。

- [ ] 先核对教程模型是否仍合适，以及本机显存和磁盘需求。
- [ ] 使用 `uv` 添加经过确认的依赖。
- [ ] 把模型、Hugging Face 和 uv 缓存放到 D 盘。
- [ ] 运行一个轻量级模型并观察 Token 编码与生成结果。
- [ ] 修改 `max_new_tokens` 和一个采样参数，比较输出。

教程正文使用的模型和章末推荐的模型不同，而且模型生态变化很快。到这个阶段再依据官方资料确定具体模型与版本。

### 阶段 8：模型选型与幻觉

阅读 `3.2.4`、`3.3` 和本章小结。

- [ ] 为“代码助手”和“本地隐私文档助手”各做一次模型选型。
- [ ] 从能力、成本、延迟、上下文、隐私和工具生态进行比较。
- [ ] 设计一次幻觉实验，区分模型生成的陈述和可验证事实。
- [ ] 对比“只问模型”和“允许 Agent 调用外部工具”的可靠性。

教程中的具体模型名单具有时效性；重点学习选型维度，实际选择时再核对最新官方资料。

## 章末优先练习

- [ ] Zero-shot、Few-shot 和采样参数对比实验。
- [ ] 简化 BPE 实验。
- [ ] 轻量级本地模型运行与参数对比。
- [ ] 幻觉缓解方案分析。

## 本章 Git 学习目标

第三章会产生多个小实验，正好用来学习“读懂历史”，每个实验单独形成一次小提交。

- [ ] 使用 `git status` 区分新文件与已修改文件。
- [ ] 使用 `git diff` 和 `git diff --staged` 比较工作区与暂存区。
- [ ] 使用 `git log --oneline` 阅读提交历史。
- [ ] 使用 `git show 提交编号` 查看一次提交。
- [ ] 比较两个提交之间修改了哪些文件。
- [ ] 解释提交编号是什么，以及 `amend` 为什么会改变编号。

建议提交粒度：

```text
docs: add chapter 3 learning plan
feat: implement bigram probability demo
feat: add attention shape experiment
feat: compare prompting strategies
feat: simulate BPE token merging
feat: run a lightweight local language model
docs: complete chapter 3 review
```
