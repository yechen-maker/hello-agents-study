## 学习原则

从第四章手写的 ReAct、Plan-and-Solve、Reflection 出发，理解框架怎样封装模型调用、工具、状态与执行流程。按教材顺序阅读 AutoGen、AgentScope、CAMEL、LangGraph，但不预设四套都安装、运行完整案例；把时间留给能帮助自己写代码、调试和做项目的部分。实际动手前再核对当前文档、版本、依赖和模型调用成本。

## 穿插安排

1. **6.1：从手写到框架。**读完 6.1.1～6.1.2 暂停。用第四章某个 Agent 举例，说出框架替你封装了什么、哪些业务逻辑仍要自己写；再用一句话区分“多 Agent 对话协作”和“显式状态图”。
2. **6.2 AutoGen：**先理解消息、角色、轮询/终止条件；读到代码前暂停，再决定是否做最小离线协作练习，不急于运行会连续消耗模型请求的完整软件开发团队。
3. **6.3 AgentScope、6.4 CAMEL：**按教材顺序理解消息传递与角色协作。若与已做练习重复，就只做结构对比；若出现新的代码概念，再插入小练习。
4. **6.5 LangGraph：**重点理解状态、节点、普通边、条件边与循环。优先用第四章 Reflection 作为对照，选择一个可验证的小流程亲手编码；不需要照搬整个在线搜索助手。
5. **6.6：**复盘框架选型：什么时候继续用纯 Python，什么时候框架能减少重复代码。根据实际完成的练习检查结果，再整理提交。

### LangGraph 离线小练习

项目已用 `uv` 加入 `langgraph`；代码不调用 LLM、搜索 API 或网络服务，没有 API 费用。

图结构是 `START → draft → review`，随后根据状态选择 `review → draft`（返工）或 `review → END`（结束）。`DraftState` 保存草稿、审查要求、尝试次数和节点轨迹。第 1 稿不含“测试”，第 2 稿补上“测试”；因此要求“测试”时会走两轮。要求“部署”时即使两轮仍不通过，也必须在上限处结束。

从 TODO 1 开始，逐个完成；节点只返回需要更新的字段，不直接修改传入的状态。检查命令：

```powershell
uv run python chapter06/check_graph_loop.py
```

已核对运行路径：`draft → review → draft → review`，第 2 稿通过。后续可自行尝试把要求词改成“功能”（一轮通过）或“部署”（两轮到上限仍不通过），观察条件边的选择。
