# 第 5 章：基于低代码平台的智能体搭建

教程：[第五章 基于低代码平台的智能体搭建](https://hello-agents.datawhale.cc/#/./chapter5/%E7%AC%AC%E4%BA%94%E7%AB%A0%20%E5%9F%BA%E4%BA%8E%E4%BD%8E%E4%BB%A3%E7%A0%81%E5%B9%B3%E5%8F%B0%E7%9A%84%E6%99%BA%E8%83%BD%E4%BD%93%E6%90%AD%E5%BB%BA)

## 本章目标

把第四章手写的模型、工具、记忆与循环，映射到可视化平台的节点和配置上。教材依次介绍 Coze、Dify、FastGPT、n8n。本章先比较，再选择**一个平台重点实操**；其他平台以理解流程和差异为主，不要求四套服务都部署。

平台界面、功能和收费可能变化。真正注册、安装或选择平台时，再核对各平台当时的官方文档与实际页面；教程截图只用于理解概念。

## 穿插安排

### 阶段 1：5.1 为什么用低代码，以及怎样选平台

先读 `5.1.1`～`5.1.2`，读完暂停。

- [ ] 用第四章的 ReAct 例子，指出哪些工作被平台封装了：模型调用、工具注册、状态保存、日志、发布等。
- [ ] 用一句话概括 Coze、Dify、FastGPT、n8n 各自的主要用途；暂不背具体功能数量。
- [ ] 结合自己的目标，从易上手、私密数据、知识库/RAG、自动化集成、部署成本中选出最重要的两项，再决定重点实操平台。

**第一个暂停点：**读完 5.1 后告诉我你最看重哪两项，以及你想先试哪个平台。选择前不安装、不注册四套平台。

### 阶段 2：5.2 Coze——插件、工作流与信息来源

- [ ] 先读 `5.2.1`，把模型、提示词、插件、知识库、工作流分别对应到第四章的代码组件。
- [ ] 读 `5.2.2` 的“每日 AI 简报”案例：画出“信息来源 → 整理 → 输出”的最小流程，指出哪一步可能需要核实来源。
- [ ] 读 `5.2.3` 后记录一个优势和一个限制。若 Coze 被选为重点平台，再做一个缩小版原型，不必一次集成所有信息源或公开发布。

### 阶段 3：5.3 Dify——应用、工具与知识库

- [ ] 读 `5.3.1`，区分模型配置、知识库、插件和工作流。
- [ ] 分段读 `5.3.2`，从“个人助手”案例中只选一个可验证功能先做最小原型，不同时做问答、文案、多模态和数据分析全部模块。
- [ ] 读 `5.3.3`，记录数据流、调试方式及部署取舍。若 Dify 是重点平台，再用测试数据运行至少三个输入案例。

### 阶段 4：5.4 FastGPT——RAG 的可视化链路

- [ ] 读 `5.4.1`，画出“导入资料 → 分块 → 检索 → 生成答案”的链路。
- [ ] 读 `5.4.2` 案例时，重点看检索结果怎样进入回答；若做资料问答原型，优先用非敏感小文档，并要求回答标注来源。
- [ ] 读 `5.4.3`，比较它与 Dify 的知识库路径。是否本地部署留到确定重点平台和设备条件后再决定。

### 阶段 5：5.5 n8n——节点、触发器与自动化

- [ ] 读 `5.5.1`～`5.5.2`，画出触发器、AI Agent、工具与输出节点之间的数据流。
- [ ] 读 `5.5.3`～`5.5.5`，识别示例内存存储重启后丢失的风险，以及什么时候需要持久化。
- [ ] 若 n8n 是重点平台，先用手动触发和模拟数据测试流程；不自动发送真实邮件或连接真实业务账户。

### 阶段 6：5.6 小结与仓库记录

- [ ] 对四个平台按“适用任务、数据位置、可扩展性、部署/使用成本”做简短对比，注明哪些判断来自实际试用、哪些仅来自教程。
- [ ] 对重点平台保存一份可复现的搭建说明：输入、节点/配置、预期输出、实际测试结果。
- [ ] 如平台允许导出工作流，可把**去除凭证和私人数据**的导出文件纳入仓库；否则保存配置说明即可。

## 本章 Git 练习

第四章已经用 `git status --short`、`git diff --cached --stat`、`git commit` 和 `git show` 保存了一份可回看的快照。第五章尝试在**平台选择、最小原型、章末对比**等阶段分别提交，而不是等全部结束再提交。每次暂存前先看 `git diff` 和文件内容，确认没有把凭证、私密数据或平台导出中的敏感字段放进公开仓库。
