# 第 9 章：上下文工程

教程：[第九章 上下文工程](https://hello-agents.datawhale.cc/#/./chapter9/%E7%AC%AC%E4%B9%9D%E7%AB%A0%20%E4%B8%8A%E4%B8%8B%E6%96%87%E5%B7%A5%E7%A8%8B)

## 本章目标

在第八章“获取记忆与外部资料”的基础上，解决“信息太多、太长，塞不进或塞进去导致模型混乱”的问题。
从单次提示词的“提示工程（Prompt Engineering）”，升级到系统化动态管理输入信息的“上下文工程（Context Engineering）”。
掌握“上下文腐蚀”与“Lost in the Middle”原理，理解 GSSC 框架（收集、筛选、结构化、压缩），并通过离线小练习亲手实现一个基于 Token/字符预算的上下文裁剪与组装器。

## 穿插安排

1. **9.1 与 9.2 概念与挑战：**读 9.1 与 9.2 后暂停。能用大白话解释“提示工程”与“上下文工程”的区别，说出“上下文腐蚀”与注意力分散的危害。
2. **9.3 GSSC 框架与动态技术：**读 9.3，理解 Gather（收集）、Select（选择）、Structure（结构化）、Compress（压缩）四步法，分清滑动窗口（Sliding Window）与按需加载（JIT）。
3. **9.4 核心实践：**亲手实现一个轻量级的上下文构建器 `context_builder_demo.py`，完成有限预算下的历史消息裁剪、优先级保留与格式化，配离线检查器验证。
4. **9.5 收尾与复盘：**复盘本章练习，记录保留与跳过的理由，执行 Git 提交与远程推送。

## 成本与环境约定

- 先做纯 Python 原生实现的上下文管理与裁剪练习；不引入复杂的外部分词模型（先用字符数/简单空白切分估算 Token）。
- 保持离线可验证，不强求调用在线大模型消耗付费 Token。
